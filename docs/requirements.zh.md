# agent-ops 需求与目标文档

[English](requirements.md) | 中文

本文档沉淀 agent-ops 的完整需求背景、设计目标、当前实现与目标形态，是后续所有
开发与评审的基准。来源：与使用者的多轮需求讨论与实现迭代。

## 1. 背景与动机

使用者是**网络工程师 / 运维工程师**，日常工作横跨两类对象：

- **服务器侧**：在超融合平台上创建虚拟机 / 容器，配置基础设置后，远程登录到
  系统内做初始化与优化（apt 清华源、npm 国内源、时区、locale、基础软件包、
  系统参数微调、加固等）。
- **网络设备侧**：对交换机、路由器等二层 / 三层网络设备做优化调整。当前做法
  是：先查相关文档 → 用 AI 生成命令 → 人工决定采用与否 → 执行配置写入。

痛点：两条工作流都需要在多套工具之间切换（文档、AI、终端、设备 CLI），
操作分散、重复劳动多、且网络设备写配置缺少统一的确认与回滚纪律。

## 2. 核心目标

**通过 DeepSeek Harness（DSH）的对话，让 Agent 直接连接并控制服务器与网络
设备，完成日常运维与优化调整。**

具体拆解为：

1. 在 DSH Web 中选择「远程运维」预设，即获得完整的远程运维工作台；
2. 服务器（SSH）与网络设备（Telnet / SSH）都能由 Agent 直接操作；
3. 网络设备配置变更遵循固定纪律：只读探测 → 候选命令 → 用户确认 → 写入 →
   验证 → 回滚；
4. 服务器初始化（国内源等）遵循：只读探测 → 变更方案 → 用户确认 → 执行 →
   验证。

## 3. 设计原则

1. **单一独立插件**：agent-ops 是一个插件（一个包、一行组合、一个侧边栏
   入口），不修改 DSH 源码，运行时**不依赖任何其他插件**——DOM 钩子、面板、
   引擎、工具全部自包含。
2. **Agent 优先、GUI 辅助**：核心能力经 Agent 工具暴露（对话驱动）；GUI 面板
   负责主机配置、交互式终端与传输等强交互场景，两者共享同一份配置数据。
3. **安全第一**：凭据私有文件存储（0600）；写配置必须显式解除只读护栏且先经
   用户确认；Telnet 明文的适用范围显式声明；输出不脱敏但提示风险。
4. **遵循 dsh 插件规范**：cordis bundle 包（cordis.patch.yml + dsh.client）、
   官方 NPM SDK、共享构建预设、双语文档、完整测试。

## 4. 功能需求清单（现状已实现）

### 4.1 SSH 能力（Linux 服务器）

| 能力 | 说明 |
| --- | --- |
| 主机管理 | 增删改查、搜索、连接测试；配置存 `~/.dsh/dsh-ssh.json`；密钥 / 密码认证、passphrase 密钥、ProxyJump 跳板机；支持导入 `~/.ssh/config` |
| 持久连接池 | 每台主机一条长连接，空闲 30 分钟断开，断线自动重连（最多 3 次） |
| 命令执行 | 超时（默认 60s），stdout/stderr 分离，2MB 输出截断保护 |
| Web 终端 | xterm.js + WebSocket PTY 终端，自适应尺寸，实时输出 |
| 文件传输 | SFTP 上传 / 下载带进度，远程目录浏览 |
| 端口转发 | 本地端口转发隧道（仅 127.0.0.1），访问远程数据库 / 内网服务 |
| 集群执行 | 一条命令并发跑多台主机（别名 / 环境 / 标签过滤） |

### 4.2 Telnet 能力（网络设备）

| 能力 | 说明 |
| --- | --- |
| 设备管理 | 增删查；配置存 `~/.dsh/dsh-telnet.json`（0600）；按厂商提示词检测（cisco / huawei / h3c / generic） |
| 登录与会话 | 用户名 / 密码登录；可选 enable / super 特权模式（含特权密码） |
| 命令执行 | 顺序执行命令；自动处理 `--More--` 分页与 `[Y/N]` 确认提示 |
| 短连接模型 | 每次执行新建连接、执行后自动退出，不占用 vty 会话 |
| 只读护栏 | `readOnly` 默认开启：拒绝 `configure terminal` / `system-view` / `save` / `write` 等写入类命令；写配置必须显式 `readOnly:false` 且先经用户确认 |

### 4.3 Agent 工具

- SSH：`ssh_add` / `ssh_list` / `ssh_exec` / `ssh_upload` / `ssh_download` /
  `ssh_tunnel` / `ssh_cluster`
- Telnet：`telnet_list` / `telnet_add` / `telnet_exec` / `telnet_remove`

### 4.4 工作流预设

`agent-remote-ops`（远程运维）预设固化两类工作流与安全纪律（探测 → 方案 →
用户确认 → 执行 → 验证；网络设备额外要求先备份、失败即回滚）。

## 5. 目标形态与实现效果（含新思路）

使用者提出并确认的演进方向：**统一连接模型**。

### 5.1 统一目标注册表

现状是「主机」（SSH）与「设备」（Telnet）两个独立注册表。目标态是**一个统一
的"目标"概念**：

- 每个目标一条记录：别名、地址、协议（ssh / telnet）、端口、凭据、
  特权模式配置、标签、环境、备注；
- **协议字段决定连接方式，端口只是协议参数**（ssh 默认 22、telnet 默认 23，
  均可自定义）；
- Agent 工具与 GUI 面板读写同一份注册表，`ssh_add` / `telnet_add` 演进为
  统一的 `target_add`（保留旧工具名兼容）；
- 数据文件迁移兼容：继续使用现有 `dsh-ssh.json` / `dsh-telnet.json`，或按
  协议字段分区存储，迁移脚本保证不丢凭据。

### 5.2 GUI 面板扩展

- 面板新增「设备」标签页，与「主机」并排，共享增删改查交互；
- 目标表单新增「协议」选择器（SSH / Telnet）：选 Telnet 时显示 Telnet 专属
  字段（enable 命令、enable 密码、设备厂商），选 SSH 时显示 SSH 专属字段
  （密钥路径、跳板机）；
- Telnet 设备提供**交互式 Web 控制台**（复用现有终端页的 xterm 基建，经
  Host 侧 Telnet 会话桥接）；
- Telnet 设备执行命令时 GUI 同样受只读护栏约束（面板内提供显式开关与确认）。

### 5.3 实现效果（用户视角）

- **一句话接入**：用户把服务器 / 设备信息丢进对话（或 GUI 表单），Agent 完成
  注册、连通性验证并汇报；
- **一个面板管两类目标**：侧边栏「远程运维」入口打开后，主机与设备在同一个
  面板内管理、测试、开终端；
- **网络设备变更全程留痕**：探测输出、候选命令、确认结果、写入结果、验证
  对比、回滚动作全部在对话中可见；
- **新协议即插即扩展**：未来加 SNMP / 串口 console 等，只需新增引擎与工具，
  注册表加协议枚举，架构不动。

## 6. 安全模型

- Telnet 明文传输：仅限可信带内管理网络；生产设备优先 SSH 管理口。
- 凭据以明文存于 `~/.dsh/dsh-ssh.json` / `~/.dsh/dsh-telnet.json`，文件权限
  0600、目录 0700（与 ssh-skill 同一信任模型）；对话中给出的密码同时留在
  会话记录，敏感环境优先密钥或 GUI 导入。
- `telnet_exec` 默认只读；写配置须显式 `readOnly:false` 且先经用户确认。
- 远程输出原样返回（不脱敏）；执行 / 传输消耗真实远程资源，先确认再操作。
- 所有 `/api/agent-ops/*` 路由仅限 loopback；隧道只监听 `127.0.0.1`。
